# MRDN 系统 · 工具开发接入规范（给 AI 看）

> **这份文档怎么用**：把这份文档 + 你的工具业务逻辑一起交给 AI，让 AI 严格按本规范写出适配 MRDN 系统的 Python 工具脚本，再打包成 exe 放进 `tools` 文件夹，系统就能直接调用。
>
> **AI 写工具时，请严格遵循以下四条铁律**：
> 1. **参数名是唯一对接关键**——`--<参数名>` 必须和 `tool.json` 里 `inputs[].id` 完全一致。
> 2. **结果必须写进 `--out_dir`**——系统只会收集这个目录下的文件，文件名固定、可预期。
> 3. **stdout 必须转 UTF-8**——Windows 打包后默认 GBK，中文 `print` 会崩。
> 4. **网页接口查询必须控制访问频率**——每次请求间隔 **1~5 秒**，模拟人工操作速度，避免高频访问被限流/封禁。**凡是涉及网页接口查询的工具，一律遵守**。

## 一、系统是怎么调用工具的（协议）

MRDN 系统通过**命令行**调用你的工具 exe：

```
<工具.exe> --<参数名1> <文件绝对路径1> --<参数名2> <文件绝对路径2> ... --out_dir <输出目录>
```

- **输入**：用户在系统里拖入的每个输入文件，系统用 `--<参数名> <绝对路径>` 传给你的工具。
- **输出**：系统会**自动追加**一个 `--out_dir <目录>` 参数，你的工具必须把结果文件写进这个目录。
- **收集**：系统运行结束后，收集 `<输出目录>` 下的**所有文件**，显示在作业台「输出文件」框，可点击预览、可打开本地文件。

**所以你的工具只需做到 3 件事：**

1. 每个输入一个 `--<参数名>` 参数（参数名 = 英文小写 + 下划线，如 `input_template`）。
2. 支持 `--out_dir`，把结果写进该目录，文件名固定、可预期（如 `输出结果.xlsx`）。
3. stdout 中文转成 UTF-8（Windows 打包后默认 GBK，中文 print 会崩）。

> ⚠️ **参数名是唯一的对接关键**：`--<参数名>` 必须和 `tool.json` 里的 `inputs[].id` 完全一致，系统就是靠它把文件路径（或平台凭证路径）传给你的工具。

## 二、工具脚本标准模板（直接复制改）

```python
# -*- coding: utf-8 -*-
"""
<工具名>（<英文名>）
=================================
功能：
    <这里写你的业务逻辑：读什么文件、算什么、输出什么结果>
依赖：
    pip install openpyxl   # 按需写
"""

#  ⚙ MRDN 系统集成参数对照表（配置系统「工具输入关联」时，照此填「参数名」）
# ============================================================================
#   参数名（填到系统）       对应文件 / 含义
#   --<参数名1>              <含义1>
#   --<参数名2>              <含义2>
#   （--out_dir 为系统自动传入的输出目录，无需在系统里配置）
# ============================================================================

import argparse


# 基础路径：打包成 exe 后，脚本同目录 = exe 所在目录

else:
    BASE_DIR = os.path.dirname(os.path.abspath(__file__))

    if hasattr(sys.stdout, "reconfigure"):

            sys.stdout.reconfigure(encoding="utf-8", errors="replace")
            sys.stderr.reconfigure(encoding="utf-8", errors="replace")
        except Exception:
            pass


def parse_args():
    p = argparse.ArgumentParser(description="<工具名>")
    # 每个输入一个 --参数名；参数名必须与 tool.json 的 inputs[].id 一致
    p.add_argument("--<参数名1>", default=None, help="<含义1> 路径")
    p.add_argument("--<参数名2>", default=None, help="<含义2> 路径")
    # out_dir 由系统自动传入，不用在系统里配置
    p.add_argument("--out_dir", default=None, help="输出目录（系统自动传入）")
    return p.parse_args()


def do_work(input1_path, input2_path):
    """核心业务逻辑：读入 -> 处理 -> 返回结果数据。"""
    # TODO: 在这里实现你的逻辑
    return []


def main():
    _configure_stdout()
    args = parse_args()

    # 输出目录：系统会传 --out_dir；不传则退回脚本同目录（方便本地双击调试）
    out_dir = args.out_dir or BASE_DIR
    os.makedirs(out_dir, exist_ok=True)
    output_file = os.path.join(out_dir, "输出结果.xlsx")   # 固定、可预期的输出名

    # 校验输入文件存在（缺了就报错退出，退出码非 0）
    for p, name in ((args.<参数名1>, "<含义1>"), (args.<参数名2>, "<含义2>")):
        if not p or not os.path.exists(p):
            print("[错误] 找不到%s：%s" % (name, p))
            sys.exit(1)

    # TODO: 调 do_work，把结果写到 output_file
    do_work(args.<参数名1>, args.<参数名2>)

    print("\n已生成输出文件：", output_file)


if __name__ == "__main__":
    try:
        main()
    except SystemExit:
        raise
    except Exception as e:
        _configure_stdout()
        print("[错误] 运行失败：%s" % e)
        sys.exit(1)
```

**要点：**

- 参数名 `<参数名1>` 等，用**英文小写 + 下划线**，见名知意。
- 文件顶部那段「⚙ 系统集成参数对照表」注释块**建议保留**，让使用者配置时一眼看到参数名对应什么。
- 输出文件名固定（如 `输出结果.xlsx`），不要带时间戳或随机后缀。
- 缺输入文件时 `sys.exit(1)`；`main` 有 try/except 兜底，异常只打印一行不刷 traceback。

## 三、三种「特殊输入」—— 除了普通文件，工具还能拿这三种东西

普通文件输入是 `--参数名 <文件路径>`。此外系统还支持三种特殊输入，在工具里声明一个参数名，运行时系统会**自动生成对应文件/参数**再传进来。这是最容易写错的地方，务必看仔细。

### 3.1 DUID 清单（`__duid_list__`）

当工具要处理「一批 DUID」（批次作业的剩余 DUID，或单 DUID 作业的当前 DUID）时，不要自己解析，而是声明一个参数名，关联到系统里的「DUID 清单」。

- 系统会**自动生成一个清单文件**（文本，每行一个 DUID），用 `--<参数名> <清单文件路径>` 传给你的工具。
- 工具里读这个文件，逐行拿到 DUID 列表。

```python
# argparse 里声明（参数名自定，如 du_list）
p.add_argument("--du_list", default=None, help="DUID 清单文件路径（系统自动生成）")

# 读 DUID 清单
def read_duids(path):
    if not path or not os.path.exists(path):
        return []
    with open(path, encoding="utf-8") as f:
        return [line.strip() for line in f if line.strip()]
```

> 配置时：在系统「工具输入关联」里，把这个参数名关联到「🎯 DUID 清单（粘贴解析的 DUID）」选项（内部值 `__duid_list__`）。

### 3.2 平台凭证（`pf_<platformId>`）—— 网页查询工具的核心

**场景**：工具要访问某个企业系统（CPQ / ISC / ISDP 等），需要带登录态 Cookie 发 HTTP 请求。

**关键理解**：Cookie **不是让用户在工具配置里手填的**。Cookie 来自系统「作业准备 → 平台网页配置」——用户在那里配置平台网址、一键登录抓取 Cookie。你的工具**不需要任何凭证类参数**（不用填 URL、Cookie、Header、method），只需要声明**一个参数名**去引用「平台凭证」。

运行时，系统会：

1. 根据用户关联的平台，把该平台的配置（url + headers 含 Cookie）写成**一个 JSON 文件**；
2. 用 `--<参数名> <JSON文件路径>` 传给工具；
3. 工具读这个 JSON，就能拿到 `url` 和 `headers`（含 Cookie），然后自己发请求。

**平台凭证 JSON 文件的结构**（工具只需读 `url` 和 `headers`）：

```json
{
  "name": "CPQ",
  "url": "https://cpq.example.com/home",
  "method": "GET",
  "headers": {
    "Cookie": "SESSION=abc123; token=xyz...",
    "User-Agent": "Mozilla/5.0 ..."
  },
  "cookie": "SESSION=abc123; token=xyz...",
  "updatedAt": "2026-10-17 19:00"
}
```

> ⚠️ **注意事项**：
> - **`headers["Cookie"]` 里就是登录态 Cookie**，直接复用整个 `headers` 发请求即可。
> - **`method` 字段不要读、不要信**：它是历史遗留的兜底值（恒为 `GET`），实际请求方式（GET/POST）由你的工具**自己写死**。
> - 企业内网通常是自签名证书，`requests` 请求记得 `verify=False`。

### 3.3 单 DUID 参数（`duid_param`）

如果工具在「单 DUID 作业」视图下运行时，希望只处理当前那一个 DUID，在 `tool.json` 里声明 `duid_param`（见第六节）。系统会自动追加 `--<duid_param> <当前DUID>` 参数。

```python
# argparse 里声明（参数名 = tool.json 的 duid_param 值，如 duid）
p.add_argument("--duid", default=None, help="只处理指定 DUID（单 DU 作业时由系统传入）")
```

## 四、网页查询工具完整模板（带 Cookie 认证，直接复制改）

这是「访问企业系统查数据」类工具的标准骨架。工具**不需要任何用户手填的凭证参数**，只需声明一个 `--platform_cfg` 参数接收平台凭证 JSON 路径。

```python
# -*- coding: utf-8 -*-
"""
网页查询工具（示例）
功能：
    读取「平台凭证」JSON（含登录态 Cookie），请求企业系统接口，导出查询结果。
依赖：
    pip install requests
"""


# ============================================================================
#  ⚙ MRDN 系统集成参数对照表
# ============================================================================
#   参数名（填到系统）       对应文件 / 含义
#   --platform_cfg           平台凭证（关联到系统「平台凭证」下拉选平台，系统自动生成 JSON）
#   （--out_dir 为系统自动传入的输出目录）
# ============================================================================

import os
import sys
import json
import argparse
import time

import requests


if getattr(sys, 'frozen', False):
    BASE_DIR = os.path.dirname(os.path.abspath(sys.executable))
else:
    BASE_DIR = os.path.dirname(os.path.abspath(__file__))


def _configure_stdout():
    if hasattr(sys.stdout, "reconfigure"):
        try:
            sys.stdout.reconfigure(encoding="utf-8", errors="replace")
            sys.stderr.reconfigure(encoding="utf-8", errors="replace")
        except Exception:
            pass


def parse_args():
    p = argparse.ArgumentParser(description="网页查询工具")
    # 唯一关键参数：平台凭证 JSON 路径（系统自动生成，不需要用户填 Cookie/URL）
    p.add_argument("--platform_cfg", default=None, help="平台凭证 JSON 文件路径（系统自动传入）")
    p.add_argument("--out_dir", default=None, help="输出目录（系统自动传入）")
    return p.parse_args()


def load_platform_cfg(path):
    """读平台凭证 JSON，返回 (url, headers, cookie)。"""
    if not path or not os.path.exists(path):
        print("[错误] 找不到平台凭证文件：%s" % path)
        sys.exit(1)
    with open(path, encoding="utf-8") as f:
        cfg = json.load(f)
    url = (cfg.get("url") or "").strip()
    headers = dict(cfg.get("headers") or {})
    cookie = cfg.get("cookie") or headers.get("Cookie", "")
    if not url:
        print("[错误] 平台凭证里没有 url，请先在「平台网页配置」里配置网址")
        sys.exit(1)
    return url, headers, cookie


def do_query(url, headers):
    """核心：用平台凭证发请求。请求方式（GET/POST）由工具自己写死。"""
    # 例：GET 查询。企业内网自签名证书 → verify=False
    resp = requests.get(url, headers=headers, verify=False, timeout=30)
    resp.raise_for_status()
    # 按接口返回类型取值：resp.json() / resp.text / resp.content
    return resp.json()


def do_query_batched(items, url, headers):
    """分批/分页查询示例：必须控制访问频率（每次请求间隔 1~5 秒）。"""
    results = []
    BATCH_SIZE = 100
    for i in range(0, len(items), BATCH_SIZE):
        batch = items[i:i + BATCH_SIZE]
        # 例：POST 查询本批。企业内网自签名证书 → verify=False
        resp = requests.post(url, headers=headers, json={"items": batch}, verify=False, timeout=60)
        resp.raise_for_status()
        results.extend(resp.json().get("data") or [])
        # ⚠️ 铁律 4：每次请求后 sleep 1~5 秒，模拟人工操作速度，避免高频访问被限流/封禁
        time.sleep(2)
    return results


def main():
    _configure_stdout()
    args = parse_args()
    url, headers, cookie = load_platform_cfg(args.platform_cfg)

    out_dir = args.out_dir or BASE_DIR
    os.makedirs(out_dir, exist_ok=True)

    data = do_query(url, headers)

    # 结果写进 out_dir（文件名固定、可预期）
    out_file = os.path.join(out_dir, "查询结果.json")
    with open(out_file, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
    print("已生成查询结果：", out_file)


if __name__ == "__main__":
    try:
        main()
    except SystemExit:
        raise
    except Exception as e:
        _configure_stdout()
        print("[错误] 运行失败：%s" % e)
        sys.exit(1)
```

**这个模板的要点（务必理解）：**

- 工具**只声明一个参数** `--platform_cfg`，用户**不需要手填 Cookie / URL / Header / method**——这些都来自「平台网页配置」，一键登录后自动抓取。
- 配置时，用户在系统「工具输入关联」里把 `platform_cfg` 这个参数名，下拉关联到「🌐 平台名（平台凭证）」即可。
- 工具读 JSON 拿到 `url` + `headers`（`headers["Cookie"]` 就是登录态），直接 `requests.get/post(...)` 发请求，**请求方式写死在工具里**。
- 如果查询需要**额外条件**（比如要查哪些 DUID），再叠加一个 `du_list` 参数关联「DUID 清单」，或叠加普通文件输入，按需增删。
- **⚠️ 访问频率（铁律 4）**：只要工具要发多次请求（分批、分页、循环查多条），**每次请求之间必须 `time.sleep(1~5)`**，模拟人工操作速度，绝不能连发高频请求。单次查询也建议在请求前/后留适当间隔。

## 六、tool.json 声明文件（强烈建议写）

在 `tools` 文件夹里，和 exe **同名**（把 `.exe` 换成 `.tool.json`）放一个声明文件：

```
tools/
  ├─ 我的工具.exe
  └─ 我的工具.tool.json      ← 文件名 = exe 名去掉 .exe 加 .tool.json
```

内容格式（以「发包配置」和「网页查询」为例）：

```json
{
  "name": "MRDN发包配置.exe",
  "display": "MRDN 发包配置",
  "duid_param": "duid",
  "inputs": [
    {"id": "input_template", "label": "输入模板", "type": "excel", "required": true},
    {"id": "output_template", "label": "输出模板", "type": "excel", "required": true}
  ],
  "outputs": [
    {"id": "result", "label": "输出结果", "file": "输出结果.xlsx"}
  ]
}
```

```json
{
  "name": "网页查询.exe",
  "display": "网页查询",
  "inputs": [
    {"id": "platform_cfg", "label": "平台凭证（关联到「平台凭证」下拉）", "type": "platform", "required": true}
  ],
  "outputs": [
    {"id": "result", "label": "查询结果", "file": "查询结果.json"}
  ]
}
```

字段说明：

- `name`：**必须是 exe 文件名（含 `.exe`）**，否则系统找不到。
- `display`：界面显示名。
- `duid_param`（可选）：声明后，单 DUID 作业自动追加 `--<duid_param> <当前DUID>`。
- `inputs[].id`：**必须和脚本 argparse 的 `--<参数名>` 一致**（唯一对接关键）。
- `inputs[].label`：中文含义，方便使用者看（`platform` 类型提示「关联平台凭证」）。
- `outputs[].file`：结果文件名，和脚本写出的文件名一致。

> `tool.json` 不是必需的。没有它，使用者也能在系统里手动「＋ 添加输入槽位」逐条配置参数名；有它，系统会自动预填好这些参数名槽位，省事。但**无论有没有 tool.json，用户都需要在「工具输入关联」里把参数名关联到具体输入项或平台凭证**。

## 七、打包成 exe

```bat
pyinstaller --onefile --noconfirm ^
  --name 英文名 ^
  --add-binary "D:\Programs\PythonHome\Library\bin\ffi.dll;." ^
  --add-binary "D:\Programs\PythonHome\Library\bin\libexpat.dll;." ^
  --add-binary "D:\Programs\PythonHome\Library\bin\libcrypto-3-x64.dll;." ^
  --add-binary "D:\Programs\PythonHome\Library\bin\libssl-3-x64.dll;." ^
  --add-binary "D:\Programs\PythonHome\Library\bin\liblzma.dll;." ^
  --add-binary "D:\Programs\PythonHome\Library\bin\libbz2.dll;." ^
  你的工具.py
```

**两个关键点：**

1. **必须带齐上面 6 个 Anaconda DLL**，否则打包后 `openpyxl` 读 Excel 时 `import pyexpat` 会崩。（网页查询工具若只 `import requests`，同样建议带上，避免依赖缺失。）
2. **先用英文名打包，再改名成中文 exe 名**（`--name 英文名` 生成 `英文名.exe`，然后手动 `rename 英文名.exe 我的工具.exe`），避免中文名打包踩坑。

打包完成后，把 `我的工具.exe`（和可选的 `我的工具.tool.json`）一起放进系统的 `tools` 文件夹即可。

## 八、在系统里配置（给使用者）

1. 把 exe + tool.json 放进 `tools` 文件夹。
2. 编辑节点 → 选工具（下拉里会出现你的 exe）。
3. 在「输入」区先**添加输入项**，把每个输入文件拖进去（工具配置只能关联本节点的输入项）。
4. 在「工具输入关联」里，把每个参数名（对照脚本顶部的参数对照表）下拉选择对应的输入项 / DUID 清单 / 平台凭证。
5. 保存 → 作业台点「▶ 运行」，结果文件会自动出现在「输出文件」框，可预览/打开。

> **网页查询工具特别说明**：它通常没有文件输入，配置时只需在「工具输入关联」里把 `platform_cfg` 关联到「🌐 平台名（平台凭证）」即可，**无需填任何 Cookie/URL**——这些已由「作业准备 → 平台网页配置」的一键登录自动抓取好。
